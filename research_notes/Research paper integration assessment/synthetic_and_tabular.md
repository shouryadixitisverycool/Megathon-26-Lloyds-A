# Synthetic-data and tabular-learning paper integration assessment

## 1. Paper identity and transferable lessons

### Assefa et al., *Generating synthetic data in finance: opportunities, challenges and pitfalls*

The supplied full text is the 2020 ICAIF introductory review by Samuel A. Assefa et al. ([ACM DOI](https://doi.org/10.1145/3383455.3422554); [J.P. Morgan copy](https://www.jpmorgan.com/content/dam/jpm/cib/complex/content/technology/ai-research-publications/pdf-8.pdf); local text: `research-papers/generating-synthetic-data-in-finance.md`). It is a framing/review paper, not a single generator algorithm: it separates realism, similarity/utility evaluation, and privacy, and surveys simulation/agent-based, statistical, GAN/VAE, and differentially private approaches (local paper §§1, 3–4, lines 112–146, 351–429, 541–600). Its useful principle is to state what the source data and threat model are, then assess utility/fidelity separately from privacy. The paper's 2020 statements about the maturity of metrics are historical, not a claim about the present research state.

### Grinsztajn, Oyallon & Varoquaux, *Why do tree-based models still outperform deep learning on tabular data?*

The supplied copy is arXiv v1 (18 July 2022), also published in NeurIPS 2022 Datasets & Benchmarks ([arXiv](https://arxiv.org/abs/2207.08815); [NeurIPS paper](https://papers.neurips.cc/paper_files/paper/2022/file/0378c7692da36807bdec87ab043cdadc-Paper-Datasets_and_Benchmarks.pdf); [authors' benchmark/code/data](https://github.com/LeoGrin/tabular-benchmark); local text: `research-papers/why-trees-outperform-deep-learning-tabular.md`). Its contribution is an empirical benchmark, not a general instruction to replace every model with a tree: 45 curated datasets, model/hyperparameter comparisons, and controlled transformations to study inductive bias. The authors report tree ensembles ahead of the compared NNs on their medium-sized regime and identify uninformative features, irregular target functions, and rotations of meaningful columns as relevant challenges (local paper §§3–5, lines 117–197, 202–258, 261–363). The paper uses roughly 400 random-search iterations per dataset and repeats the ordering 15 times (lines 161–179); dataset curation excludes, among other things, missing data and time-series tasks, so the result does not directly settle those settings (lines 120–158). The integration lesson is fair, budget-aware comparison on the task at hand—not a costly attempt to reproduce their benchmark or a universal tree-superiority claim.

Overall, the repo already applies the paper's most relevant safe lesson: make the synthetic origin, public source, generator parameters, and limits visible. The strongest unclosed question is behavioral fidelity, which cannot be resolved against real banking outcomes with the current synthetic-only inputs. The fixed independent generator perturbation is valuable, but it only tests robustness to the perturbations deliberately encoded by its authors.

Submission implication: the model-family comparison is a sensible product-level baseline exercise, but not a paper-style model benchmark. The unequal search effort (four logistic settings versus one fixed XGBoost configuration) is a disclosed limitation if comparative superiority is discussed. Do not add deep learning merely to mirror the paper: the local evidence is synthetic, product-specific, and currently selects logistic regression for each core product. Also preserve the paper-card warning that synthetic test scores—including strong Solar discrimination—measure performance under this simulator, not real-world predictive quality or fairness certification (`DATA_CARD.md:152–155`; `RESPONSIBLE_AI.md:3–13`).

## 3. Staged actions, acceptance criteria, and payoff

1. **Low effort / high submission payoff — reconcile model descriptions and pin evidence to the current implementation.** Change the card/report template or source documentation so it names XGBoost and its fixed `hist` configuration (or make a deliberate model change and then document that instead). Regenerate the model cards, consolidated evaluation and manifest together from the same code revision. Acceptance: every card/report identifies the learner/configuration and selected version; candidate scores match the generated `reports/ml_evaluation.json`; the manifest hashes the matching artifacts; and the report states that metrics/labels are synthetic and that selection uses validation ROC-AUC/Brier. Add a source revision identifier to the run evidence if it is intended to establish source-to-artifact provenance: current `RUN_MANIFEST.json` hashes outputs but does not identify the source revision.

2. **Moderate effort / conditional payoff — make the local tree comparison more budget-fair only if model comparison is a judging criterion.** Add a small, deterministic, predeclared XGBoost parameter search on the existing training/validation split; keep the same per-product population, logistic candidate, calibration/threshold policy, and final test untouched until one-time reporting. Use a bounded search (not the paper's 20,000-compute-hour research benchmark); record the budget, seed and selected configuration. Acceptance: tests establish that candidate tuning/selection/calibration cannot read test labels (extend the invariant in `tests/ml/test_propensity.py:265–280`); reports compare ROC-AUC, PR-AUC, Brier/ECE and the operational P@10%/Lift@10% on the same cohort, plus current shift/missingness diagnostics; retain logistic/heuristic if they win. This improves local selection fairness without needing neural models.

3. **High effort / defer — private-data fidelity and privacy work only if private records enter scope.** First establish lawful access, a defined entity/event adjacency and threat model, and a held-out real reference cohort. Only then choose an appropriate synthesis/privacy method and specify a privacy budget plus utility and disclosure-risk acceptance tests. With no such data or data-release requirement now, neither a learned generator nor a DP implementation has a justified near-term payoff; public aggregate marginal checks and explicit non-claims are the proportionate evidence.

**Current verdict:** existing work substantially satisfies the useful simulation, provenance, and baseline-comparison lessons. The main immediate submission risk is ambiguous model-family wording; the main scientific limit is synthetic-only validity. Report no privacy guarantee, fairness certification, or real-world efficacy from these artifacts.
